# assistant-android (placeholder name — rename before this ships)

Native Android companion app for a personal-assistant backend: bearer-authed streaming chat over SSE, with reminders/calendar/email arriving as backend tool calls the UI renders, not client-side logic. Built on ICM — see `assistant-backend`'s own `CLAUDE.md` for the method if you haven't seen it before.

**This repo never reads `assistant-backend`'s Python.** Everything it needs from that repo is copied here already — see the table below.

## Where things live

| Folder | What it holds |
|---|---|
| `docs/plan.md` | The full approved design (both repos) — section 2 ("Android app") and section 3 (build order) are this repo's load-bearing parts |
| `docs/adr/` | Decisions 001–007 (the Android-relevant subset — 008–011 are backend-only memory/secrets concerns, not copied here) |
| `docs/CONTRACT.md` | **The SSE wire contract. Read this, not the backend's Python, for anything about the chat API shape.** Copied from the backend repo — if it looks stale, re-copy, don't guess. |
| `phases/` | Build order, in execution order (`00_...` → `03_...`). Each phase folder is a contract: what it reads, builds, and how a human verifies it's done |
| `app/`, `core/`, `feature/`, `backend-client/` | The actual Kotlin modules (created starting at phase `00_project-skeleton`) |

## Route by what just happened

| If | Go to |
|---|---|
| Starting the next phase of work | The lowest-numbered `phases/*/CONTEXT.md` that has no `REPORT.md` sibling yet |
| Asked "what's actually done" | Scan `phases/*/` for a `REPORT.md` — its presence *is* the done signal |
| Need the exact SSE event shapes, request/response bodies | `docs/CONTRACT.md` only |
| Need to understand *why* something is structured a certain way | `docs/adr/` |
| Need the full design (module layout, streamed-chat pattern in prose, verification steps) | `docs/plan.md` §2 and §3 |
| Need a real bearer token to test against the live backend | Ask Mason — it's generated by `assistant-backend/scripts/gen_bearer_token.py`, never committed anywhere |

## The one rule

A phase isn't done until its `CONTEXT.md`'s human-check has actually been run and a `REPORT.md` written recording it. Don't start the next phase on the assumption the last one "should" work.
